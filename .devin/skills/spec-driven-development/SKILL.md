# Spec-Driven Development

## The Gated Workflow
1. **Specify**: Write what/why/constraints/success criteria. Get approval.
2. **Plan**: Architectural decisions, tech choices, risks.
3. **Tasks**: Small testable increments with acceptance criteria.
4. **Implement**: One task at a time, verify against spec.

## Keeping the Spec Alive
- Update spec when reality diverges
- Get re-approval on scope changes

## Red Flags
- Coding without a spec
- Spec diverges from implementation
- Skipping the approval gate
